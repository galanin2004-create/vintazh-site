# Винтаж — Галерея Галаниной

Сайт галереи винтажной одежды во Владимире. Собран по бренд-буку
«Винтаж — Галерея Галаниной», редакция 1.0 (файл
`Бренд-бук Винтаж (один файл).html`).

## Где живёт

https://galanin2004-create.github.io/vintazh-site/

Деплой автоматический: любой push в `main` запускает
`.github/workflows/pages.yml` — сборка статики и выкладка на GitHub Pages.
Адрес сайта для canonical и sitemap задаётся там же переменной
`NEXT_PUBLIC_SITE_URL`; при переезде на свой домен её и `BASE_PATH`
нужно убрать.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3220
```

Сборка:

```bash
npm run build                 # обычная сборка Next.js
STATIC_EXPORT=1 npm run build # статика в out/ — кладётся на любой хостинг
```

Если сайт отдаётся из подпапки (например, GitHub Pages), задайте базовый путь:

```bash
BASE_PATH=/vintazh-site NEXT_PUBLIC_BASE_PATH=/vintazh-site STATIC_EXPORT=1 npm run build

# в Git Bash на Windows добавьте MSYS_NO_PATHCONV=1,
# иначе /vintazh-site превратится в путь Windows
```

## Что внутри

| Страница | Путь | Что показывает |
| --- | --- | --- |
| Главная | `/` | Лок, позиционирующая формула, три принципа, новые поступления, «История вещи», три оси навигации, порядок покупки |
| Каталог | `/catalog` | Все вещи + фильтр по двум осям одновременно, сортировка, счётчики |
| Карточка вещи | `/catalog/<slug>` | Кадры вещи, «История вещи», характеристики и мерки, бронь |
| О галерее | `/about` | Бренд-стори, критерии отбора, честность о дефектах, три сегмента аудитории |
| Визит и бронь | `/visit` | Как проходит бронь, примерка, оплата и отправка |
| Контакты | `/contacts` | Телефон, Telegram, VK, приём вещей на продажу |
| Бронь | `/order?item=<slug>` | Форма брони: имя, контакты, город, способ получения, комментарий |

Плюс `sitemap.xml` и `robots.txt` — генерируются автоматически.

## Бронь и CRM

Кнопка «Забронировать эксклюзив» ведёт на `/order?item=<slug>`. Форма шлёт
заявку POST-запросом на адрес из `NEXT_PUBLIC_ORDER_ENDPOINT`. Приёмник —
отдельный проект `Desktop/vintazh-crm` (PHP + SQLite): там же список заявок
и карточки покупателей.

Если переменная не задана — а в сборке для GitHub Pages это так и есть, —
форма не ломается: она открывает Telegram с уже заполненным текстом заявки.
Локально проверять так:

```bash
php -S localhost:8300 -t vintazh-crm/site vintazh-crm/router-dev.php
```

а в `.env.local` витрины прописать
`NEXT_PUBLIC_ORDER_ENDPOINT=http://localhost:8300/api/orders`.

## Как соблюдён бренд-бук

* **Цвет** (полоса 05): тушь `#16130F`, старое золото `#A9793C`, бумага
  `#F6F3EE`, пыль `#8C857B`, лён `#DED6C9`. Бордо `#6E2A2A` использован
  только для «Продано». Пропорция примерно 70 / 22 / 8: золото идёт на
  линии, рубрики и кнопки, крупных золотых плашек нет. Градиентов нет.
* **Шрифты** (полоса 06): Prata — заголовки, названия вещей, цены.
  Manrope — текст, интерфейс, рубрики. Типографическая шкала (H1 56/62,
  H2 34/42, название вещи 22/28, текст 17/27, рубрика 12/16 с трекингом
  0.3em, кнопка 14/18 с трекингом 0.24em) вынесена в переменные в
  `app/globals.css`.
* **Тон голоса** (полоса 07): главное действие — «Забронировать
  эксклюзив», второе — «Спросить о вещи в Telegram», проданное —
  «Забрано · вещь ушла». Слов «секонд-хенд», «скидка», «успей» нет
  нигде, восклицательных знаков в текстах нет.
* **Навигация** (полоса 09): бренд-бук задаёт три оси — страна, эпоха,
  тип вещи. Ось «Эпоха» убрана по просьбе владелицы: год по вещам не
  определяется. Оставшиеся две работают одновременно, есть чипы активных
  фильтров и «Сбросить фильтры». Как вернуть эпоху — написано в
  `data/taxonomy.ts`.
* **История вещи** (полоса 10): в карточке стоит сразу под названием и
  ценой, до характеристик, с подписью «История вещи».
* **Интерфейс** (полоса 11): метки «Один экземпляр», «Тяжёлый
  люкс», «Продано»; hover главной кнопки уходит в тушь.
* **Фото** (полоса 12): кадрирование 3:4, четыре кадра на вещь —
  целиком, спина, фактура, деталь с износом.

## Что нужно заменить перед публикацией

1. **Данные по девяти жилетам.** Реальные вещи из папки «Японские вещи →
   Жакеты» уже на сайте с фотографиями и описаниями по кадру. Не хватает
   состава, размера и состояния — карточка честно пишет
   «уточняется», а вместо цены показывает «Цена по запросу». Проставьте
   поля `price`, `era`, `material`, `size`, `condition` в `data/items.ts`.
   Заодно замените рабочие названия («Жилет в меловую полоску,
   тёмно-синий») на свои, если они звучат иначе.
2. **Остальной каталог.** Двадцать семь позиций ниже жилетов —
   демонстрационные: цены, мерки и истории придуманы, фотографий нет,
   стоят заглушки. Бренд-бук прямо запрещает выдуманные факты о
   происхождении — замените их на реальные вещи или удалите.
3. **Ещё кадры.** У каждого жилета пока один кадр. Бренд-бук требует
   минимум четыре: целиком, спина, фактура, деталь с износом. Добавьте
   файлы в `public/items/<slug>/` и перечислите в `photos` — полоса
   превью появится сама.
4. **Категории.** Списки в `data/taxonomy.ts` взяты из бренд-бука как
   черновые. Замените на фактический перечень; структура трёх блоков при
   этом не меняется.
5. **Домен.** Значение по умолчанию — `vintazh-galanina.ru` в `lib/site.ts`.
   Пока сайт стоит на GitHub Pages, адрес подменяется переменной
   `NEXT_PUBLIC_SITE_URL` в workflow.
6. **Адрес галереи.** На сайте написано «приезд по звонку», точный адрес
   не указан. Если адрес публичный — добавьте его в `lib/brand.ts` и на
   страницу контактов, заодно имеет смысл поставить карту.
7. **Обмен и возврат.** На странице «Визит и бронь» написано нейтрально:
   «условия уточняйте до оплаты». Формулировку стоит согласовать с
   юристом — для б/у вещей правила отличаются от обычной розницы.

## Замеченное расхождение в бренд-буке

Полоса 04 говорит: «Инверсия. На чёрном фоне и на тёмных фотографиях.
Золото остаётся золотым». Но приложенный файл инверсной версии
(`public/logo-inverse.svg`) собран в две краски — тушь и бумага, золота
в нём нет. Сейчас в подвале стоит именно этот файл, как он есть. Если
золото в инверсии нужно — попросите у дизайнера обновлённый файл.

## Структура

```
app/            страницы, глобальные стили и стили блоков
components/     Header, Footer, карточка товара, каталог, галерея вещи
components/ui/  заглушка фото, метки, иконки, появление при скролле
data/           items.ts — каталог, taxonomy.ts — три оси навигации
lib/            brand.ts — контакты и формулировки, useUrlQuery — фильтры в адресе
public/         логотипы из бренд-бука
```

Все контакты и формулировки главных кнопок лежат в `lib/brand.ts` —
меняются в одном месте, а не по компонентам.
